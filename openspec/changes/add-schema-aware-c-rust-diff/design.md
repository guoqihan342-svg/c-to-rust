## Context

`require-ci-c-oracle-generation` proved that GitHub Actions can build and run the pinned FlashDB C oracle. The next gap is comparability: C currently emits a C-specific report and Rust `diff` still compares whole files. That is too brittle for real C/Rust migration work and does not use accepted differences.

## Goals / Non-Goals

**Goals:**

- Create a small C/Rust comparable fixture with deterministic KVDB and TSDB operations.
- Make C oracle consume that fixture and emit replay-compatible step results.
- Make Rust diff schema-aware for the replay subset.
- Fail CI when C and Rust differ on non-accepted behavior fields.
- Preserve existing Rust self-diff and 10000-loop stress behavior.

**Non-Goals:**

- This change does not prove byte-for-byte FlashDB sector layout equivalence.
- This change does not support arbitrary JSON fixtures.
- This change does not migrate all FlashDB APIs or full TSDB status edge cases.

## Decisions

### Decision 1: Add a comparable fixture instead of forcing all smoke operations

Use `fixtures/c-rust-smoke.json` for the first C/Rust behavior diff. It avoids operations known to be layout-specific and keeps TSDB range behavior in the defined forward direction.

### Decision 2: Compare selected step fields

Rust diff compares step `id`, `op`, `status`, `code`, and behavior fields such as `value`, `count`, `entries`, `entry_id`, and `timestamp`. It ignores report-level metadata and fields listed in accepted differences.

### Decision 3: Keep dependency-free parser for now

Continue using narrow parsers because all current reports are generated by this repository. If fixture complexity grows, a later change may add `serde_json`.

## Risks / Trade-offs

- [Risk] C and Rust TSDB ids are not inherently the same. -> Mitigation: C runner uses deterministic fixture-local synthetic ids for append order.
- [Risk] C FlashDB iteration order may differ from Rust ordering. -> Mitigation: first comparable fixture avoids KV entries comparison or sorts/synthesizes where needed.
- [Risk] Accepted differences could hide bugs. -> Mitigation: only skip named fields, not whole steps.

## Migration Plan

1. Add `fixtures/c-rust-smoke.json`.
2. Update C oracle to consume the fixture and output replay-compatible step objects.
3. Update Rust diff to compare step fields and accepted differences.
4. Update CI to run Rust replay for the C/Rust fixture, generate C oracle, then diff the two reports.
5. Validate locally through WSL producer, Rust tests, OpenSpec, 10000-loop stress, and GitHub Actions.
